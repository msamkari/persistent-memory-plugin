# Changelog

## 1.9.0 (2026-11-17)
Archive-before-write now covers files OUTSIDE the project. Found in use: a scheduled task's `SKILL.md` under the user's home Claude folder was overwritten with no backup, because the archive helper only accepted files inside the project. Backward compatible; no new dependency; the existing `archive.sh` commands behave as before. A red-team round on the first cut of this release found one medium and ten low issues; the fixes are included in this same version.
- archive-external: `scripts/sh/archive-external.sh <absolute-path> [--root DIR] [--to DIR] [--date D] [--write]` (Node: `scripts/archive-external.mjs`) copies one outside file into the project's archive folder (the first rule's `to` folder of `MDs/archive.json`, or `--to`) as `external_<parent folder>_<name>_<6-char hash of the origin path>_<date><a|b|c>[.ext]` and appends `<sha256>  <archive name>  <date>  <origin path>` to `external_manifest.txt` there. It is a separate entry that NO skill lists in `allowed-tools`, so Claude Code asks the user before every run. The pre-approved `archive.sh` / `archive.mjs` reject `--external` with a clear message (R4-M1: before, the pre-approved pattern could copy any readable file, such as a private key, into the project, or drop a file into `.claude/commands`).
- Refused (R4-M1): credential-like places, by file name or any parent folder: `.ssh`, `.aws`, `.gnupg`, `.azure`, `.kube`, `.docker`, `.netrc`, `.npmrc`, `.git-credentials`, `.password-store`, `.credentials*`, `id_rsa` / `id_dsa` / `id_ecdsa` / `id_ed25519`, `*.pem` `*.key` `*.p12` `*.pfx` `*.ppk` `*.kdbx` `*.jks`, `.env*`, names containing token / secret / password, password-manager names, browser profile folders (User Data, Login Data, Cookies, Firefox, Chromium, Brave, Opera, Vivaldi, Profiles). One generic message that does not echo the path. The check runs on the given path and on the real long path (so an 8.3 short name cannot hide a folder). A `--to` that is not one of the project's archive folders (the `to` folders of `archive.json`, or the defaults), or that is under `.claude` or `.git`, is refused. Without `--write` the command checks the path text only and never looks at the outside file (no way to ask whether a file exists); a missing file is reported only with `--write`.
- Hardening: a hard-linked manifest (more than one link) is refused (R4-L10); the manifest is opened and checked before anything is published, and if its line cannot be written the new copy is removed and the command fails (R4-L1); a `:` after the drive (alternate data stream, `::$DATA`, `::$INDEX_ALLOCATION`) is refused (R4-L2, L4); the extension is kept only when it is 1 to 16 letters or digits and the whole name goes through the `[A-Za-z0-9._-]` filter (R4-L2, L8); the origin in the manifest is percent-encoded for control, C1, line-separator, bidi and zero-width characters, `%` and runs of spaces, so a line always has exactly four fields (R4-L5); the name carries a hash of the full origin path so tasks with Arabic or other non-ASCII folder names are told apart (R4-L6); the source is hashed while copied and again afterwards, and size and time are compared; a source that changed (same-inode rewrite) fails and the partial copy is deleted (R4-L7); files over 256 MB are refused and hashes are streamed (P2); file system errors print a short code, not full paths (R4-L8). The real (long) path is resolved and used for the inside-the-project check and the manifest, so a case or 8.3 spelling of a project file is treated as inside (R4-L3, L4). On Windows a path must start with a drive letter (a rooted path without one, `\Users\...`, is refused); a short (8.3) path is accepted and recorded under its real long name (this corrects the first text, which said it was refused).
- Also refused, as before: a relative path, a path starting with two slashes or backslashes, control characters, a symlink or junction anywhere on the source path (checked folder by folder from the drive root), a device name, a folder, a missing file, a file inside the project (use the plain form), a manifest that is a link or folder, an archive folder that is a link or outside the project. An existing archive name is never overwritten (the next letter is taken). Without `--external` a path outside the project is refused exactly as before.
- skill `memory-archive`: section "Files outside the project" rewritten: the separate command and its approval prompt, what to do on FAIL (do not edit the original; report the reason), a restore step through the manifest, the month sub-folder, an outside-file trigger in the description, "does not delete: use it before a delete" (replaces "Not for deleting"), and a plain statement that archiving `SKILL.md` does not save a scheduled task's schedule or enabled flag (write those in the project note when known). Skill `memory-continuity` (the main skill is pinned by a hash test and was not edited): one rule: archive a scheduled task, a user-level settings file or any outside file a project process depends on before editing or deleting it, and never reuse a real scheduled task as a test fixture.
- tests: `tests/external-archive.test.mjs` (15, adapted to the new name and entry) and `tests/external-archive-hardening.test.mjs` (15 new: the pre-approved command rejects `--external`, the new script is in no allowed-tools, credential paths, no existence oracle in plan mode, `--to` limits, hard-linked manifest, unwritable manifest, `:` streams, name and extension sanitising, manifest encoding, Arabic folder names, rewrite during copy, size cap, Windows paths, short errors). The two skill-text tests that scan commands now exempt `archive-external.sh` on purpose. The CI list has the new file.
- Verified (run here, Windows, Node 24, temp folders only): the tests above, with real hard links, real read-only manifests, real junctions. Not verified: macOS and Linux runs (CI covers them after a push, not yet pushed); a real scheduled task was not touched or used (by design); the Claude Code approval prompt itself (a live session) - it follows from the command not being in any `allowed-tools`, the same mechanism as every other non-listed command; a race by another process between open and copy is tested only through the test seams (the rewrite-in-place case is real); two sessions appending at the same instant was tested in the red-team round on the first cut, not repeated; the model following the new skill text was not run.
- Known limits (not fixed, with the reason): a mapped network drive letter (`Z:\share\...`) is not detected as a network path (P1; Windows opens it before any check, a full fix needs a drive-type call that Node does not offer without a dependency); macOS `/tmp` and `/var` (and some Linux `/home`) are symbolic links, so files under them are refused (P3; the safe direction); a manifest swapped for a link between the check and the write is narrowed by writing through the checked handle but not proven closed on every system (P4); the `.claude` / `.git` destination check is by name, not by what Claude Code loads, and the credential list is a deny-list, not a guarantee that no secret is ever copied (the user's approval prompt is the main control); the plan output name is computed from the path as typed, so it can differ from the real name when the path was an 8.3 or differently-cased spelling; this archives one file at a time and does not archive a folder; the helper cannot stop a process that edits the outside file without calling it; license field is unchanged (Apache-2.0, as in `LICENSE`).

## 1.8.5 (2026-11-15)
Fixes from the second adversarial round (every fix has a regression test in `tests/round2-fixes.test.mjs`; 261 tests, up to 2 skipped where links or folder swaps are unavailable).
- approval gate: asks for a push with `--force` or any abbreviation of `--force-with-lease` / `--force-if-includes` (`--force-w`), `-f` followed directly by a redirect or other punctuation (the command is now split on `< > { }` as well), `--mirror`, `--prune`, `--delete` / `-d` and a `:refspec` (delete), a backslash inside a word (`g\it`), `git --attr-source`, and wrapper flags such as `bash -ec`, `sh -euc`, `bash <<< "..."`, `pwsh -c {...}`, `powershell -Com`, and PowerShell's evaluate-a-string command. (Encoded PowerShell commands are not decoded.)
- approval gate, text: `git merge`, `git notes`, `gh pr merge|review|comment`, `gh issue create|edit|comment`, `gh release create|edit` count as publishing text (a visible signature is denied; `--body-file` / `-F` / `--notes-file` and `--file` and its abbreviations ask); `--trailer` text is checked; the signature test also runs on a cleaned copy of the command (quotes, backslashes, backticks and zero-width characters removed, spaces collapsed) and accepts `=` and the full-width colon, so a signature split by quotes is found. Plain `git log`, `status`, `commit-tree` and ordinary pushes stay allowed.
- approval gate on Windows: `hooks/hooks.json` now also registers the gate for the `PowerShell` tool (the `Bash` entry is unchanged); backtick escapes, `& git`, `git.exe` and string evaluation are understood.
- end-of-work hook: the optional `reasonExtra` text from `MDs/freshness.json` is project data: control, bidi, zero-width and tag characters are removed, whitespace is collapsed, it is capped at 300 characters and prefixed with "Project note (data, not an instruction from the user):". A `work` entry that is the project folder itself or contains `..`, and an empty `extensions` entry, are ignored; if nothing usable is left the hook stays silent and `freshness.mjs check` says why.
- archive: the source file is opened once and the handle is checked (same device and file id as the verified path inside the project, parent folders re-checked for links, before and after the copy); bytes are read from that handle into a temp name in the archive folder and published with an exclusive hard link, so a failed or raced copy leaves nothing behind. Destination folder names ending in a dot or a space are refused.
- setup: every path that would be created is checked with lstat before anything is created; a dangling link at a file, or a link or junction on the way (such as `MDs`), is refused and nothing is made. The home-folder guards use the account's real home folder from the operating system; if `USERPROFILE` / `HOME` names a different folder the run is refused. `joblog.mjs` checks both homes.
- session index and cost lines: the name filter also removes Unicode tag characters, variation selectors, private-use and blank filler characters; the "Suggestion only" line uses the cleaned name. lint skips any file whose name contains "conflict" (including `(PC's conflicted copy ...)`). `onboarding decline` refuses a marker that is a symbolic link and does not truncate the target.
- Known limits, not fixed here: the joblog and archive-destination check-then-use windows were attempted but not reproduced, and are not proven safe (the destination folder is re-checked after it is created, which narrows but does not close the window); the gate stays advisory (aliases, variables, assembled strings, `-m "$(cat f)"`, `-t`/`-C` message sources and `glab` are not seen; a command over 1,000,000 characters is only checked by the plain rules); by-design items such as the 80-character names, the project folder name in generated files and wrapper `*` argument patterns are unchanged; a disk-full condition was not tested; a hard-linked source file is still accepted by archive; the end-of-work `state` and file names are cleaned but still shown. The junction-swap regression test is skipped on Windows (the system refuses to rename a folder that holds an open file); the file-replacement variant runs everywhere.

## 1.8.4 (2026-11-15)
Fixes from an adversarial test round (every fix has a regression test; 236 tests, 1 skipped where links are unavailable).
- archive: `scripts/archive.mjs` refuses a source file or a destination (`--to`, or an `archive.json` rule `to`) whose path passes through a symlink or junction, or resolves outside the project, like `joblog.mjs` already did. Message, exit 1, nothing written.
- archive arguments: `--root`, `--date`, `--to` without a value, unknown flags (a typo such as `--wirte`), extra arguments, a date that is not a real calendar date, a `--to` that is a Windows device name (CON, NUL, COM1...) or starts with `//` or two backslashes are usage errors (exit 1).
- approval gate: now understands git options that take a separate value (`-C dir`, `-c k=v`, `--git-dir`, `--work-tree`), `git.exe`, combined short flags (`-fu`, `-uf`), `+refspec` pushes, quoted forms (`"--force"`, `git "push"`) and commands wrapped in another shell invocation. A commit message from a file (`git commit -F`, `--file=`) or a PR text from `gh pr create --body-file` / `gh api -f body=` asks (the gate cannot read it); a visible signature is still denied. The old rules still run (on commands up to 20,000 characters, so a hostile huge input cannot make them slow); huge inputs are tested to stay fast and fail open.
- lint: Arabic-Indic digits (U+0660-0669, offset 1584; the old offset produced control characters, so numbering such as `(٣)` and a reference such as `بند ٩٩` were silently ignored) and Persian digits (U+06F0-06F9, offset 1728) are normalised; a read-only target in `--apply` ends with a clean FAIL and RESULT line instead of a stack trace; a `02_* (conflicted copy)` file is not taken as the log.
- `.gitignore` added (`evals/results/`, which holds local paths, plus OS and editor files).
- session hook: file names echoed into the model context (index and the "Largest" cost line) lose control, bidi and zero-width characters, whitespace is collapsed and each is capped at 80 characters; the hand-over line no longer prints the absolute project path.
- end-of-work hook: a file counts as written by this session only when the transcript path, resolved against the project root, is that exact file (no loose suffix match); `<scheduled-task` is looked for only in the first user message.
- activity: `tail` accepts only a positive whole number (a negative one printed the wrong lines); an `activity.jsonl` that is a directory gives a clean error.
- Known limits, not fixed here: the gate is advisory (aliases such as `git pf`, variables, assembled strings and Unicode look-alikes are not seen); joblog/archive/lint can still modify state files and archives as documented (append-only design); joblog checks only the last 4 KB for NUL; `setup.mjs` follows a junction at `MDs`; the git history still contains one commit by a different author and PR merge commits with a different committer identity (needs a history rewrite, the owner's decision); the end-of-work hook can exceed its own timeout on an unreachable network transcript path.

## 1.8.0 (2026-11-13)
- New skill `memory-log` and `scripts/joblog.mjs`: appends ONE line to a job log inside `Jobs/` or `MDs/` (`.md`, `.txt`, `.log`) with the text carried as an argument or on stdin, so scheduled and unattended sessions need no `printf >>` through the shell. It appends through a single append-mode open (existing bytes never change), and works only in the folder the session runs in (`--root` must be `CLAUDE_PROJECT_DIR`, the current folder or a folder inside it).
- It refuses: `..`, absolute, drive, UNC, extended-length (`\?\`) and `:` paths, Windows device names (including COM1 to 9 and the superscript forms), symbolic links and junctions (file or any folder on the way), hard-linked files, files that are not UTF-8 text, line breaks, control characters (C0 and C1), U+FFFD, lines over 2000 characters, files outside `Jobs/` and `MDs/`, other extensions, and a missing file unless `--create` (which never creates folders). It removes invisible direction and formatting characters, Unicode tag characters, soft hyphens and word joiners (zero-width joiner and non-joiner are kept for Arabic and Persian), keeps CRLF files CRLF, and finishes a last line that had no line ending. A start through a link, a junction or another letter case still runs (it used to be possible to exit 0 without writing). No network, no other process.
- Why: a scheduled task asked for permission on a `printf >>` line. Tested with `claude -p`: the shell redirect itself needs approval (even for plain text and even with a broad `Bash(printf:*)` rule), while one `node` command does not. A broad printf rule would also let a session write any file. Recommended permission rule: the full stable path of the script, never a leading wildcard.
- Directory readiness (found by the plugin directory's submission checks): every skill's `allowed-tools` now pre-approves only its own plugin script (`Bash(node ${CLAUDE_PLUGIN_ROOT}/scripts/<name>.mjs *)`, the commands in the skills are written in the same unquoted form; tested live with `claude -p`), never `Bash(node:*)`, and `memory-setup` no longer pre-approves `Edit`. Scripts and hooks no longer touch the whole environment object: they read named variables only (`scripts/envpick.mjs`). The approval gate is documented, and tested, as able only to deny or ask, never to approve. New `docs/PRIVACY.md` and `docs/PRIVACY.ar.md` (privacy, support, terms) linked from `plugin.json` (`privacyPolicyUrl`, `supportUrl`, `termsOfServiceUrl`). Listing icon (1024x1024 PNG, generated with Gemini, chosen by the author). New `tests/directory-readiness.test.mjs` (6 tests). 212 tests in total.
- Second review fixes: the session folder is `CLAUDE_PROJECT_DIR` when set, otherwise the current folder (never both); the home folder, drive roots and links to elsewhere are refused as roots; lone surrogates are refused; the emoji variation selector is kept while more hiding places (variation selectors supplement, Hangul and Khmer fillers, Braille blank) are removed; device names with spaces, `CONIN$` and `CONOUT$` are refused; two writers creating the same new file both land; stdin waits at most 3 seconds; a start whose real path cannot be confirmed now says so instead of exiting silently. The permission rule and the command use the same unquoted form with the path of your own clone.
- Honest limits (also in the script header): on Windows a link swapped in by a process that can already write inside the project between the check and the open is not detected; two writers on a file without a final line ending can leave one blank line.
- Tests: `tests/joblog.test.mjs` (35: shell-hostile and Arabic text, 52 refused path forms each checked against its own refusal reason, links, junction start, hard links, CRLF, 20 concurrent writers with and without a final newline, root restriction, hidden-character smuggling, exit codes, a source check that writes only through one append open). `node tests/mutation/joblog-mutations.mjs` (manual) breaks the script 23 ways: 21 are caught, 2 are second layers that only a race or a short write could reach and are listed as known. 206 tests in total (211 after the directory-readiness tests below). Added to CI.

## 1.7.0 (2026-11-13)
- One install, every project. The plugin is meant to be installed once at user scope; a project needs no copy of it. New page `docs/onboarding.md`.
- SessionStart hook: in a folder that looks like a project and has no memory system, it now adds one note, once per project, so Claude offers the setup in one sentence. It only does this where the hook printed nothing before (no memory folder set, no HANDOVER.md). It stays silent in the home folder and above it, drive roots, Desktop / Documents / Downloads and sync-folder roots, hidden and application-data folders, system folders, folders with no files, inside a project (or a subfolder of one) that already has `MDs/System_Current_MD`, `MDs/freshness.json`, `Jobs/state_manifest.json` or a hand-over file, and whenever the plugin's data folder is unknown or cannot be written.
- The hook now writes for the first time, and only in the plugin's own data folder (`CLAUDE_PLUGIN_DATA`): one marker per project, `onboarding/<hash>.json`, holding a state word and a date, no path and no project name. It is written before the offer is printed; if it cannot be written, nothing is offered. Nothing is ever written in the project by a hook. The README section "What runs on your computer" says so in both languages.
- New `scripts/onboarding.mjs` (`status`, `decline`, `reset`, `off`, `on`). `PMS_SETUP_OFFER=off` silences the offer; `PMS_SETUP_OFFER=always` also shows it to users who set a memory folder (by default their output is byte-identical to 1.6.1).
- New skill `memory-setup` and `scripts/setup.mjs`: prints a plan and writes nothing; with `--write`, after the user's yes in chat, creates only what is missing (`MDs/HANDOVER.md` with one "Start here" block, `Jobs/series_log.md`, `Jobs/state_manifest.json`, `MDs/System_Current_MD/`, `MDs/System_Previous_MDs/`, `Jobs/_Archive/`, `MDs/archive.json`, and `MDs/freshness.json` unless `--no-freshness`). Never overwrites, refuses the home folder and system folders, English or Arabic file text.
- New skill `memory-archive` and `scripts/archive.mjs`: archive before write. Copies a file to the folder named by the project's `MDs/archive.json` under `<name>_YYYY-MM-DD` plus a same-day letter (a, b, c; or the main skill's plain, b, c), never overwrites a copy, never touches the original, verifies the copy by SHA-256, and stops on a broken config. `memory-lint --apply` keeps its own archive step unchanged.
- Optional companion `vitals` (a separate plugin): the setup skill offers its starter config when it is installed and otherwise says how to install it. The plugin never installs it and runs no other program.
- Setup offer reminder (decided by Mohammad): if nobody answers the first offer, one reminder is shown after 14 days (second marker file `<hash>.2.json`, exclusive create); a `decline` is never reminded; `reset` clears both.
- Tests: three new files, `tests/onboarding.test.mjs` (34), `tests/setup-archive.test.mjs` (21, including a made-up project taken from the offer through setup, the Stop hook and the archive) and `tests/onboarding-docs.test.mjs` (8); 171 tests in total. They are added to CI.
- Not changed: the Stop hook, the approval gate, `scripts/freshness.mjs`, the main skill `persistent-memory-system` (still pinned by hash), `memory_dir`, `hooks/hooks.json`. A project that already has a memory system gets the same hook output as in 1.6.1.
- Not yet verified: the offer in a real interactive Claude Code session (the tests run the hook as a process), macOS and Linux (CI will run them), Cowork.

## 1.5.0 (2026-10-29)
