# Changelog

## 1.8.0 (2026-11-13)
- New skill `memory-log` and `scripts/joblog.mjs`: appends ONE line to a job log inside `Jobs/` or `MDs/` (`.md`, `.txt`, `.log`) with the text carried as an argument or on stdin, so scheduled and unattended sessions need no `printf >>` through the shell. It appends through a single append-mode open (existing bytes never change), and works only in the folder the session runs in (`--root` must be `CLAUDE_PROJECT_DIR`, the current folder or a folder inside it).
- It refuses: `..`, absolute, drive, UNC, extended-length (`\?\`) and `:` paths, Windows device names (including COM1 to 9 and the superscript forms), symbolic links and junctions (file or any folder on the way), hard-linked files, files that are not UTF-8 text, line breaks, control characters (C0 and C1), U+FFFD, lines over 2000 characters, files outside `Jobs/` and `MDs/`, other extensions, and a missing file unless `--create` (which never creates folders). It removes invisible direction and formatting characters, Unicode tag characters, soft hyphens and word joiners (zero-width joiner and non-joiner are kept for Arabic and Persian), keeps CRLF files CRLF, and finishes a last line that had no line ending. A start through a link, a junction or another letter case still runs (it used to be possible to exit 0 without writing). No network, no other process.
- Why: a scheduled task asked for permission on a `printf >>` line. Tested with `claude -p`: the shell redirect itself needs approval (even for plain text and even with a broad `Bash(printf:*)` rule), while one `node` command does not. A broad printf rule would also let a session write any file. Recommended permission rule: the full stable path of the script, never a leading wildcard.
- Directory readiness (found by the plugin directory's submission checks): every skill's `allowed-tools` now pre-approves only its own plugin script (`Bash(node ${CLAUDE_PLUGIN_ROOT}/scripts/<name>.mjs *)`, the commands in the skills are written in the same unquoted form; tested live with `claude -p`), never `Bash(node:*)`, and `memory-setup` no longer pre-approves `Edit`. Scripts and hooks no longer touch the whole environment object: they read named variables only (`scripts/envpick.mjs`). The approval gate is documented, and tested, as able only to deny or ask, never to approve. New `docs/PRIVACY.md` and `docs/PRIVACY.ar.md` (privacy, support, terms) linked from `plugin.json` (`privacyPolicyUrl`, `supportUrl`, `termsOfServiceUrl`). New `tests/directory-readiness.test.mjs` (5 tests). 211 tests in total.
- Second review fixes: the session folder is `CLAUDE_PROJECT_DIR` when set, otherwise the current folder (never both); the home folder, drive roots and links to elsewhere are refused as roots; lone surrogates are refused; the emoji variation selector is kept while more hiding places (variation selectors supplement, Hangul and Khmer fillers, Braille blank) are removed; device names with spaces, `CONIN$` and `CONOUT$` are refused; two writers creating the same new file both land; stdin waits at most 3 seconds; a start whose real path cannot be confirmed now says so instead of exiting silently. The permission rule and the command use the same unquoted form with the path of your own clone.
- Honest limits (also in the script header): on Windows a link swapped in by a process that can already write inside the project between the check and the open is not detected; two writers on a file without a final line ending can leave one blank line.
- Tests: `tests/joblog.test.mjs` (35: shell-hostile and Arabic text, 52 refused path forms each checked against its own refusal reason, links, junction start, hard links, CRLF, 20 concurrent writers with and without a final newline, root restriction, hidden-character smuggling, exit codes, a source check that writes only through one append open). `node tests/mutation/joblog-mutations.mjs` (manual) breaks the script 23 ways: 21 are caught, 2 are second layers that only a race or a short write could reach and are listed as known. 206 tests in total (211 after the directory-readiness tests below). Added to CI.

## 1.7.0 (2026-11-13)
- One install, every project. The plugin is meant to be installed once at user scope; a project needs no copy of it. New page `docs/onboarding.md`.
- SessionStart hook: in a folder that looks like a project and has no memory system, it now adds one note, once per project, so Claude offers the setup in one sentence. It only does this where the hook printed nothing before (no memory folder set, no HANDOVER.md). It stays silent in the home folder and above it, drive roots, Desktop / Documents / Downloads and sync-folder roots, hidden and application-data folders, system folders, folders with no files, inside a project (or a subfolder of one) that already has `MDs/System_Current_MD`, `MDs/freshness.json`, `Jobs/state_manifest.json` or a hand-over file, and whenever the plugin's data folder is unknown or cannot be written.
- The hook now writes for the first time, and only in the plugin's own data folder (`CLAUDE_PLUGIN_DATA`): one marker per project, `onboarding/<hash>.json`, holding a state word and a date, no path and no project name. It is written before the offer is printed; if it cannot be written, nothing is offered. Nothing is ever written in the project by a hook. The README section "What runs on your computer" says so in both languages.
- New `scripts/onboarding.mjs` (`status`, `decline`, `reset`, `off`, `on`). `PMS_SETUP_OFFER=off` silences the offer; `PMS_SETUP_OFFER=always` also shows it to users who set a memory folder (by default their output is byte-identical to 1.6.1).
- New skill `memory-setup` and `scripts/setup.mjs`: prints a plan and writes nothing; with `--write`, after the user's yes in chat, creates only what is missing (`MDs/HANDOVER.md` with one "Start here" block, `Jobs/series_log.md`, `Jobs/state_manifest.json`, `MDs/System_Current_MD/`, `MDs/System_Previous_MDs/`, `Jobs/_Archive/`, `MDs/archive.json`, and `MDs/freshness.json` unless `--no-freshness`). Never overwrites, refuses the home folder and system folders, English or Arabic file text.
- New skill `memory-archive` and `scripts/archive.mjs`: archive before write. Copies a file to the folder named by the project's `MDs/archive.json` under `<name>_YYYY-MM-DD` plus a same-day letter (a, b, c; or the main skill's plain, b, c), never overwrites a copy, never touches the original, verifies the copy by SHA-256, and stops on a broken config. `memory-lint --apply` keeps its own archive step unchanged.
- Optional companion `vitals` (a separate plugin): the setup skill offers its starter config when it is installed and otherwise says how to install it. The plugin never installs it and runs no other program.
- Setup offer reminder (decided by Mohammad): if nobody answers the first offer, one reminder is shown after 14 days (second marker file `<hash>.2.json`, exclusive create); a `decline` is never reminded; `reset` clears both.
- Tests: three new files, `tests/onboarding.test.mjs` (34), `tests/setup-archive.test.mjs` (21, including a made-up project taken from the offer through setup, the Stop hook and the archive) and `tests/onboarding-docs.test.mjs` (8); 171 tests in total. They are added to CI.
- Not changed: the Stop hook, the approval gate, `scripts/freshness.mjs`, the main skill `persistent-memory-system` (still pinned by hash), `memory_dir`, `hooks/hooks.json`. A project that already has a memory system gets the same hook output as in 1.6.1.
- Not yet verified: the offer in a real interactive Claude Code session (the tests run the hook as a process), macOS and Linux (CI will run them), Cowork.

## 1.6.1 (2026-11-01)
- Stop hook: work written by a subagent that this session started is now counted. Claude Code keeps a subagent's tool calls in its own transcript (`<session>/subagents/agent-*.jsonl`), so before this fix a file updated only through a subagent (for example by the memory-keeper agent) was invisible and the hook allowed the turn to end. The hook now reads those files too, within the same time and size limits, and an unreadable subagent file never breaks the check.
- Path matching now compares Unicode-normalised (NFC) text, so a decomposed file name in the transcript matches the composed name on disk.
- `docs/end-of-work.md`: says plainly that the block repeats on every turn while the state files are behind (once per turn, not once per session), that the hook does not override the permission system (update the files with Edit/Write if a shell command is refused), and lists the remaining limit: a shell write by relative path after `cd` is not counted.
- Tests: `tests/end-of-work-hook.test.mjs` 24 -> 30 (subagent write, subagent read-only, subagent shell write, unreadable subagent entry, NFD name, Arabic names with spaces); two deliberate breaks (no subagent scan, no NFC) were each caught.
- `README.ar.md` brought back in line with `README.md`: it now has the same sections (social preview image, "See it run", the full parts table including the Stop hook, install elsewhere, two names, common errors, Safety, Tests, features by version, optional extras). The English README was also corrected: the Windows limitation no longer says the hooks were never tried in a real session, the test count is current, and the Stop hook is described as blocking once per turn.
- Tests: 3 new checks in `tests/trust-docs.test.mjs` keep the two READMEs aligned (same number of sections, same linked docs and images, every skill and hook named, same test count); two deliberate breaks were caught. 108 tests in total (107 pass, 1 skipped as before).
- Found by simulated edge-case runs of the hook (10 cases; the subagent gap and the NFD name are fixed here, the relative-path-after-`cd` gap is documented). Not changed: the approval gate, the SessionStart hook, the skills.

## 1.6.0 (2026-11-01)
- Trust documentation: new README section "What runs on your computer" (English and Arabic) and a note in INSTALL step 4. It explains the "includes components that run code" notice that Claude shows for any plugin with hooks, and lists, per hook, what it reads, what it writes and that none uses the network. Checked against the hook sources: no network or process-spawning code in `hooks/` or `scripts/`.
- Skill `notebooklm-reference` rewritten as a guide, not a connector. It now states first that there is no official Claude connector for a personal NotebookLM account, starts with a safe manual path, and treats unofficial third-party tools as an advanced, approval-gated option with explicit risks (undocumented interfaces, terms of service, a saved login session on disk, a separate Google account recommended). It also tells Claude to correct any earlier suggestion to upload memory files.
- The skill no longer sets `disable-model-invocation`, so Claude can load it when the user asks about NotebookLM instead of improvising an answer (a user session did exactly that and suggested uploading memory files). It installs nothing by itself.
- The Arabic README no longer says the hooks were never tried in a real Claude Code session: the Stop hook was tried in real sessions on Windows (four cases), the SessionStart hook was seen working there, the approval gate was not.
- Fixed a bug found by `claude plugin validate --strict`: the `description` line of skill `memory-activity` contained a bare `: `, which is invalid YAML, so Claude loaded that skill with empty metadata (name, description and flags silently dropped). The description is now a block scalar with the same meaning.
- Added `tests/trust-docs.test.mjs` (8 tests, in CI; each was checked by deliberately breaking it, 7 of 7 breaks were caught): hook events match the README tables, no network or process code in `hooks/` and `scripts/`, the NotebookLM skill keeps its "no official connector" and privacy rules, every skill's description is valid YAML, and the version matches in plugin.json, both READMEs and this changelog. 99 tests in total (98 pass, 1 skipped as before).
- Not changed: hooks, scripts, the main skill `persistent-memory-system`.

## 1.5.0 (2026-10-29)
- Added an opt-in Stop hook, `hooks/end-of-work.mjs`. It is silent in every project unless that project has `MDs/freshness.json` (state files and work files, see `docs/end-of-work.md`). When it is configured and this session wrote a work file after the state files (HANDOVER, manifest, ...) were last updated, the hook blocks ending the turn once and names the files. It never blocks twice (`stop_hook_active`), never stops scheduled-task runs, counts only files this session wrote (parsed from the transcript's tool calls, not mere mentions or reads), and fails open on any error, bad config, missing file or time bound.
- Added `scripts/freshness.mjs` (shared logic, read-only, no network) with two commands: `init` (prints a suggested `MDs/freshness.json`; `--write` creates it only if absent, never overwrites) and `check` (the same comparison by hand, exit 0/1/2). Config key `disabled: true` switches the hook off per project.
- Skill `memory-continuity`: new optional step 6 (ask first), template `templates/freshness.json`, and a HANDOVER template section "Keeping these files current". The main skill file is unchanged.
- Added `tests/end-of-work-hook.test.mjs` (24 tests, in CI; each protection was checked by deliberately breaking it); 91 tests in total.
- Why: an "update the project files when you finish" rule written only in prose was forgotten in long sessions, and a file-structure inventory said "pass" while the state files were stale.
- Not changed: the SessionStart hook, the approval gate, the main skill `persistent-memory-system`, `memory_dir`. Without `MDs/freshness.json` nothing happens.
